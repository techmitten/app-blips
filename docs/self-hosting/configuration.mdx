You can change how the browser version of AppBlips behaves with a `.env` file: a plain text file with one `NAME=value` setting per line. This works when you run [from source](/quickstart-source) or with [Docker](/self-hosting/docker).

**Every setting is optional.** With no `.env` file, you pick your provider, key and model in **Settings → AI** and everything works. The desktop app doesn't read `.env` at all.

## Create the file

1. Copy `.env.example` to `.env` in the AppBlips folder.
2. Fill in only the lines you need.
3. Restart AppBlips. From source, stop it with `Ctrl+C` and run `npm start` again. With Docker, run `docker compose up -d`.

At startup the server prints which provider and model it found. It never prints your key.

## AI provider for the server

Set these to give the server its own AI provider. People then see a **Free (no key needed)** option in setup and in **Settings → AI**. A key someone enters in **Settings → AI** always wins over this one.

<Warning>
  Anyone who can open your copy can build with this key, and your provider bills you. Keep AppBlips on your own computer (the default) and set a spending limit in your provider's dashboard.
</Warning>

<ParamField body="OPENAI_API_KEY" type="string">
  Your provider's API key. For most providers, the start of the key tells AppBlips which one it is:

  - `sk-ant-`: Anthropic
  - `sk-proj-`, `sk-svcacct-`, `sk-admin-`: OpenAI
  - `AIza`: Gemini
  - `xai-`: xAI
  - `sk-or-`: OpenRouter
  - anything else: DeepSeek, unless you set `OPENAI_LLM_PROVIDER` or `OPENAI_BASE_URL`
</ParamField>

<ParamField body="OPENAI_LLM_MODEL" type="string">
  The model to build with, named exactly as your provider names it, such as `deepseek-v4-pro`. Empty means the provider's newest general model. Required when you set `OPENAI_BASE_URL`.
</ParamField>

<ParamField body="OPENAI_LLM_PROVIDER" type="string">
  Pick the provider yourself: `deepseek`, `openai`, `anthropic`, `gemini`, `xai` or `openrouter`. Use `openai` for an older OpenAI key that starts with plain `sk-`.
</ParamField>

<ParamField body="OPENAI_BASE_URL" type="string">
  The address of any service that speaks the OpenAI chat-completions API, such as `https://openrouter.ai/api/v1`, or your own vLLM or LiteLLM. Set `OPENAI_LLM_MODEL` too.
</ParamField>

<ParamField body="OPENAI_LLM_VISION_MODEL" type="string">
  A second model, on the same service and key, used only for requests with an image. Use it when your main model can't read images.
</ParamField>

<ParamField body="OPENAI_LLM_TEMPERATURE" type="number" default="0.0">
  How much the AI varies its answers. `0.0` is the most predictable. Fix-up requests always use `0.0`, and models that don't accept a temperature never get one.
</ParamField>

<ParamField body="APPBLIPS_MAX_OUTPUT_TOKENS" type="number">
  The exact output limit, in tokens, for every request that uses the Free option. When set, the **Output tokens** fields in **Settings → AI** are hidden and ignored while Free is in use. Requests with a visitor's own key are not affected: they always use the visitor's own setting. Empty lets each person choose, with 64,000 as the default for building. Don't set it much lower than 64,000, or long builds can stop unfinished.
</ParamField>

Examples:

<CodeGroup>
```bash Anthropic
OPENAI_API_KEY=sk-ant-...
```

```bash DeepSeek
OPENAI_API_KEY=sk-...
OPENAI_LLM_MODEL=deepseek-v4-pro
```

```bash OpenRouter
OPENAI_API_KEY=sk-or-...
OPENAI_LLM_MODEL=anthropic/claude-sonnet-5
```

```bash Another service
OPENAI_BASE_URL=https://example.com/v1
OPENAI_API_KEY=your-key
OPENAI_LLM_MODEL=your-model
```
</CodeGroup>

If a service rejects builds, set **Reasoning** to **Off** in [Settings → AI](/reference/settings#reasoning). Some services don't accept the reasoning setting AppBlips sends.

## Limits on the Free option

On a server other people can reach, the Free option is limited so one person can't use up your budget. People who use their own key are never limited. Each visitor is counted by IP address, or by account if you turn on [sign-in](#sign-in-for-the-free-option). Counts live in memory, so a restart resets them.

These limits always apply and can't be changed. Each is per visitor:

- 6 chat messages a minute
- 3 seconds between messages
- 120 AI requests an hour
- 4 requests at once

You can turn all limits off, or add token caps:

<ParamField body="APPBLIPS_FREE_LIMITS" type="string" default="on">
  Set to `off` to remove every limit. Do this when only you use the server.
</ParamField>

<ParamField body="APPBLIPS_FREE_TOKENS_PER_IP_PER_DAY" type="number">
  Tokens one visitor may use per day (midnight to midnight UTC). A token is a small piece of text, about three-quarters of a word. Empty or `0` means no cap.
</ParamField>

<ParamField body="APPBLIPS_FREE_TOKENS_PER_DAY" type="number">
  Tokens everyone together may use per day (UTC). Empty or `0` means no cap.
</ParamField>

<ParamField body="APPBLIPS_FREE_MAX_OUTPUT_TOKENS" type="number">
  The most output tokens for one Free request. It only lowers a larger limit, such as the 64,000 default or a visitor's own setting, and never raises a smaller one. Empty keeps the app's own limit. If `APPBLIPS_MAX_OUTPUT_TOKENS` is also set, the lower of the two applies.
</ParamField>

## Sign-in for the Free option

On a public server, you can require a Google or GitHub sign-in before someone uses the Free option, and the limits then count each account. Sign-in is provided by [Clerk](https://clerk.com). People with their own key never sign in. It's off unless both keys below are set.

<Steps>
  <Step title="Create a Clerk application">
    Make a free account at [clerk.com](https://clerk.com) and add an application.
  </Step>
  <Step title="Allow only Google and GitHub">
    In the dashboard's sign-in options, switch on **Google** and **GitHub** and switch off everything else.
  </Step>
  <Step title="Copy the keys into .env">
    Under **API keys**, copy the **Publishable key** and the **JWT public key** into the settings below, then restart AppBlips.
  </Step>
</Steps>

<ParamField body="CLERK_PUBLISHABLE_KEY" type="string">
  Starts with `pk_live_` or `pk_test_`. It isn't secret.
</ParamField>

<ParamField body="CLERK_JWT_KEY" type="string">
  The PEM public key from **API keys → JWT public key**. The server uses it to check sign-ins itself. In `.env`, write line breaks as `\n` to keep it on one line.
</ParamField>

<ParamField body="APPBLIPS_FREE_SIGN_IN" type="string">
  Set to `off` to turn sign-in off but keep the keys in place.
</ParamField>

A sign-in only works from the address your copy is opened at. If you serve it from other addresses, list them in `APPBLIPS_CHAT_ALLOWED_ORIGINS`.

<Accordion title="Optional: add new users to a Resend email list">
  If you set a Clerk webhook (Clerk dashboard → Webhooks) to `POST /api/webhooks/clerk`, AppBlips can add new and updated users to a Resend audience.

  - `CLERK_WEBHOOK_SIGNING_SECRET`: the webhook's signing secret.
  - `RESEND_API_KEY`: your Resend API key.
  - `RESEND_AUDIENCE_ID`: the audience to use. If empty, the first audience in your Resend account is used.
</Accordion>

## Photo library

<ParamField body="UNSPLASH_ACCESS_KEY" type="string">
  The Access Key of an Unsplash app you register at [unsplash.com/developers](https://unsplash.com/developers). With it, the AI uses real, credited Unsplash photos in websites and apps. Nobody needs an Unsplash account, and games don't use it. Everyone on your server shares the key's hourly limit: 50 requests for a new app, 1,000 once Unsplash approves it. You don't need the Secret Key.
</ParamField>

<ParamField body="APPBLIPS_PHOTO_LIBRARY_URL" type="string" default="https://web.appblips.com">
  For the desktop app, which holds no Unsplash key: the AppBlips server their photo searches go to. Set it to `off` to turn the photo library off.
</ParamField>

## Server

<ParamField body="PORT" type="number" default="3000">
  The port `npm start` listens on. Docker ignores it. Use `APPBLIPS_PORT` instead.
</ParamField>

<ParamField body="APPBLIPS_PORT" type="number" default="3000">
  Docker only. The port on your computer where you open AppBlips.
</ParamField>

<ParamField body="HOST" type="string" default="127.0.0.1">
  `npm start` only. The network address the server listens on. The default lets only your own computer connect. Change it only if you put your own sign-in in front. See [Security](/self-hosting/security#if-you-open-appblips-to-other-devices).
</ParamField>

<ParamField body="APPBLIPS_ALLOWED_HOSTS" type="string">
  AppBlips only answers when opened as `localhost`, `127.0.0.1` or `[::1]`. To use another name, such as a reverse proxy's domain, list it here. Separate names with commas, without `http://` or a port. Example: `appblips.home.example`.
</ParamField>

<ParamField body="APPBLIPS_CHAT_ALLOWED_ORIGINS" type="string">
  AppBlips refuses AI requests that come from any page but its own. If a reverse proxy changes the address the server sees, builds can fail with `Requests from other sites are not allowed.` List the exact address you open AppBlips at, separated by commas. Example: `https://appblips.home.example`.
</ParamField>

<ParamField body="APPBLIPS_DATA_DIR" type="string" default="~/.appblips">
  Older AppBlips versions stored saved keys here. Keys now stay in your browser, and the server deletes any old key files from this folder at startup. You don't need to set it. The Docker image uses `/data`.
</ParamField>
