This page explains what protects your API key and your computer, and what you need to do yourself if you run your own copy.

## Your API key

An API key is a secret code that lets AppBlips use your account with an AI provider. In every version, AppBlips never writes it into the apps you build, your saved projects or anything you export.

- **Desktop app:** the key is encrypted with your computer's keychain and stored only on your computer. Only the app's background process reads it. On Linux without GNOME Keyring or KWallet, the encryption is weak, and AppBlips warns you.
- **Browser version** ([web.appblips.com](/quickstart-browser), [from source](/quickstart-source) or [Docker](/self-hosting/docker)): the key is saved in your web browser, for that address only. It is not encrypted, so anyone who can use your browser profile on that computer could read it. Use a computer and browser profile only you use. Each request carries it to the server, which passes it to your provider and doesn't store it. The same goes for your Surge sign-in for [Publish](/features/publishing), your Pollinations sign-in, and your Pixabay and Tavily keys. One person's keys never reach another person on the same server.
- **Android app:** the key is kept in the Android Keystore.

Clearing your browser data for AppBlips removes saved keys. So does **Settings → Danger Zone → Factory Reset** in either version.

## Generated apps run in a sandbox

Apps you build run in an isolated preview frame, not inside AppBlips. An app can't read AppBlips' page, cookies or browser storage (where the browser version keeps your keys), and it can't use your key to call your provider. **Open in new tab** uses the same isolation.

<Warning>
  An exported app is an ordinary HTML file with full permission to run scripts. Open it as a local file or host it on its own website. Never serve it from the same address as the browser version of AppBlips, where it could read what AppBlips keeps in the browser.
</Warning>

## The desktop app

The desktop app opens no network port, so other devices can't reach it. AppBlips doesn't limit how many requests it sends with your own key, so set a spending limit in your provider's dashboard.

## Running the browser version yourself

The server you start from source or with Docker has no sign-in, so it's set up to answer only you:

- It listens on `127.0.0.1` only. Docker publishes it as `127.0.0.1:3000`. Other devices on your network can't connect.
- It only answers when opened as `localhost`, `127.0.0.1` or `[::1]`. This stops a website from pointing its own domain at your computer to reach AppBlips.
- It refuses AI requests that come from other websites.
- It rejects oversized requests: over 32 MB for chat, over 72 MB for anything else.
- The [SEO](/features/tools#seo) scan only visits public internet addresses on the normal web ports (80 and 443), so it can't be used to read pages on your own network.

### If you open AppBlips to other devices

You open it up if you change `HOST`, remove `127.0.0.1:` from `docker-compose.yml`, or add names to `APPBLIPS_ALLOWED_HOSTS`. From then on, anyone who can reach it can use it. If you gave the server its own AI provider in `.env`, they can build with that key at your expense.

<Warning>
  Put your own sign-in in front first, for example a reverse proxy with a password.
</Warning>

If you share a server on purpose:

- Everyone's own keys stay in their own browser, so nobody can use anyone else's.
- The **Free** option, which uses the server's provider, has per-visitor limits. See [Limits on the Free option](/self-hosting/configuration#limits-on-the-free-option).
- You can require a Google or GitHub [sign-in for the Free option](/self-hosting/configuration#sign-in-for-the-free-option) so limits count each account.
- You can cap reply length for everyone with `APPBLIPS_MAX_OUTPUT_TOKENS`. See the [configuration reference](/self-hosting/configuration).
- Set a spending limit with your provider. It's the final safeguard.

## Microphone and voice input

Voice input listens only while you've switched it on with the microphone key. Speech is turned into text on your computer, and the recording is never uploaded or saved.

- In the desktop app, only AppBlips' own screen can use the microphone, and only for sound. The preview where generated apps run is refused, and nothing can use the camera.
- In the browser version, the preview frame has no microphone permission either.
- The speech model (Whisper base, about 76 MB) is downloaded from Hugging Face the first time you agree to it. AppBlips downloads one fixed version and checks every file against a stored SHA-256 fingerprint before using it.
