Code signing adds a digital signature to a program, so your computer can tell who made it and that nobody changed it.

## What's signed

- **Windows (Microsoft Store):** signed by Microsoft. Windows installs it without warnings and the Store keeps it updated. The [Microsoft Store](https://apps.microsoft.com/detail/9nk9ss4v2n1k) is the only way to install AppBlips on Windows. The `AppBlips-Windows-Installer.exe` on each GitHub release is Microsoft's small Store installer. It installs the Store version, not a separate build.
- **Linux (AppImage and `.deb` from GitHub):** not code-signed. Linux doesn't warn about that, and you can [check the download](#check-that-your-download-is-genuine) instead.
- **Linux (Snap):** installed and updated through the Snap Store, which is what Ubuntu's App Center uses.

## How releases are built

Releases are built automatically on GitHub's servers from the [`TechMitten/app-blips`](https://github.com/TechMitten/app-blips) repository, by the [Desktop workflow](https://github.com/TechMitten/app-blips/blob/master/.github/workflows/desktop.yml). Nobody builds the files by hand.

The workflow builds the AppImage, `.deb` and Snap on Linux and the Store package on Windows. It publishes only if every build succeeds:

- The Store package goes to Microsoft for review. After Microsoft signs and approves it, it's published through the Store.
- The Snap goes to the Snap Store.
- The AppImage and `.deb` go into a draft GitHub release. The project owner, [@TechMitten](https://github.com/TechMitten), publishes it on the [Releases page](https://github.com/TechMitten/app-blips/releases).

## Check that your download is genuine

This applies to the AppImage, `.deb` and Windows installer you download from GitHub. The Store and Snap Store check their own packages.

Each release includes `SHA256SUMS.txt`, which lists a fingerprint for each of those files. If your file's fingerprint matches, it's exactly what the workflow built.

1. Download `SHA256SUMS.txt` from the same release as your file.
2. Open a terminal in the folder with your download.
3. Run `sha256sum` followed by a space and the file name.
4. Compare the long code it prints with that file's line in `SHA256SUMS.txt`. They should be identical.

## Privacy

AppBlips sends your prompts and projects only to the AI provider you set up in **Settings → AI** (or, with **Free (no key needed)**, the one chosen by whoever runs that copy). It also connects to a few other services, for example for updates and code libraries. See [What does AppBlips connect to?](/reference/faq#privacy) for the full list.
