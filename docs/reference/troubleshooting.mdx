Look for the message or symptom you see. If nothing here helps, [find the error details](#find-the-error-details) and [report a bug](https://github.com/TechMitten/app-blips/issues/new).

## Windows installer is blocked

**Windows blocks an AppBlips installer from GitHub.** Old versions offered an unsigned `.exe` on GitHub, which Windows 11's Smart App Control can block. It no longer gets updates.

1. In the old copy, open **Settings → Data** and click **Export** to back up your projects.
2. Install [AppBlips from the Microsoft Store](https://apps.microsoft.com/detail/9nk9ss4v2n1k). It's signed by Microsoft and the Store keeps it updated.
3. In the new copy, open **Settings → Data** and click **Import…**.

Linux doesn't use Smart App Control, so the AppImage and `.deb` aren't blocked this way.

## Saving and finding projects

<AccordionGroup>
  <Accordion title="My projects disappeared (browser version)">
    The browser version saves projects in your browser, separately for each address. Check that you:

    - Opened the same address as before, including the port. `localhost` and `127.0.0.1` count as different addresses.
    - Used the same browser, not a private window.

    Clearing your browser's data for that address deletes the projects. Back up now and then with **Settings → Data → Export**.
  </Accordion>

  <Accordion title="&quot;This project could not be saved: the browser's storage for AppBlips is full&quot;">
    Your browser has run out of room. Your latest change isn't saved yet.

    1. Open **Settings → Data** and click **Export** to back up.
    2. Delete apps you don't need.
    3. Try again.

    The [desktop app](/quickstart-desktop) saves to folders on your computer and doesn't have this limit. The same fix applies to `Browser storage is full. Delete some apps or use the desktop app.` when you import a backup.
  </Accordion>

  <Accordion title="&quot;… failed: … Your latest changes may not be saved to disk&quot; (desktop app)">
    AppBlips couldn't write to your projects folder.

    1. Open **Settings → Data** and look at **Projects folder**.
    2. Make sure that folder exists and you can save files in it. If it's on a removable drive, plug the drive in.
    3. Or click **Change…** to pick another folder.

    On the Snap version, `EACCES: permission denied` for a path like `~/snap/appblips/1/.config/appblips/Projects` can mean it's using an older Snap revision's folder. Update AppBlips in App Center, then close and reopen it. Export unsaved work from **Settings → Data** first.
  </Accordion>
</AccordionGroup>

## Running from source or Docker

<AccordionGroup>
  <Accordion title="&quot;Port 3000 is already in use&quot;">
    Another program is using port 3000. Start AppBlips on another port.

    - **From source** (macOS or Linux): `PORT=3001 npm start`. On Windows PowerShell: `$env:PORT=3001; npm start`. Then open `http://localhost:3001`.
    - **Docker:** add `APPBLIPS_PORT=3001` to a `.env` file and run `docker compose up -d` again. See [Use another port](/self-hosting/docker#use-another-port).

    A new port is a new address, so it starts with no projects. Export them from the old address first (**Settings → Data**).
  </Accordion>

  <Accordion title="&quot;This address isn't allowed&quot;">
    AppBlips only answers on `localhost` and `127.0.0.1`. Open [http://localhost:3000](http://localhost:3000). To use another name, such as behind a reverse proxy, add it to `APPBLIPS_ALLOWED_HOSTS` in `.env` and restart. See the [Configuration reference](/self-hosting/configuration#server).
  </Accordion>

  <Accordion title="&quot;Requests from other sites are not allowed.&quot;">
    AppBlips thinks the request came from another website. This usually happens behind a reverse proxy. Add the exact address you open AppBlips at to `APPBLIPS_CHAT_ALLOWED_ORIGINS` in `.env` and restart. See the [Configuration reference](/self-hosting/configuration#server).
  </Accordion>

  <Accordion title="&quot;AppBlips isn't set up yet&quot;">
    No AI provider is set up. Open **Settings → AI**, choose a provider, paste your API key, pick a model and click **Save**. See [Choose an AI provider](/ai-providers).

    If you gave the server a provider in `.env`, the rest of the message says what's missing or wrong. Fix it and restart. See the [Configuration reference](/self-hosting/configuration#ai-provider-for-the-server).
  </Accordion>

  <Accordion title="npm install or npm start fails">
    Run `node --version`. AppBlips needs Node.js 22.12 or newer. Install the **LTS** version from [nodejs.org](https://nodejs.org/), delete the `node_modules` folder and run `npm install` again.
  </Accordion>

  <Accordion title="npm run desktop on Linux fails with a chrome-sandbox error">
    Some systems, such as Ubuntu 24.04, need Electron's sandbox helper to belong to root. In the AppBlips folder, run:

    ```bash
    sudo chown root:root node_modules/electron/dist/chrome-sandbox
    sudo chmod 4755 node_modules/electron/dist/chrome-sandbox
    ```

    Then run `npm run desktop` again. Don't use `--no-sandbox`: it turns off a safety feature.
  </Accordion>

  <Accordion title="docker-compose fails with &quot;No module named 'distutils'&quot;">
    Type `docker compose` with a space, not `docker-compose`. The hyphenated tool is old and retired. If `docker compose` is an unknown command, install the Compose plugin (on Ubuntu: `sudo apt install docker-compose-v2`).
  </Accordion>
</AccordionGroup>

## Preview problems

<AccordionGroup>
  <Accordion title="The preview is blank after a build">
    The app's code probably has an error. AppBlips fixes most of these by itself. If it stays blank:

    1. Send a follow-up, such as `The preview is blank. Fix any JavaScript errors`.
    2. Click the camera button next to the prompt box to attach a screenshot, so the AI sees what you see.
    3. Still blank? Click **Previous version** and try your prompt again with more detail.

    <Tip>
      The **Code** tab shows the code, and **Edit** lets you fix it yourself. No tab? Turn on **Code view** in **Settings → Workspace**.
    </Tip>
  </Accordion>

  <Accordion title="A link in the preview doesn't go anywhere">
    The preview keeps links inside your project. A link to another page of your website opens that page, links to other websites open in a new tab, and a link to a page that doesn't exist does nothing.

    Ask for the fix in the chat, for example `The "Pricing" link should open the pricing page`. In the App and Game studios, ask for screens inside the app instead of links.
  </Accordion>
</AccordionGroup>

## Voice input

<AccordionGroup>
  <Accordion title="&quot;The voice model could not be downloaded. Check your internet connection and try again.&quot;">
    The first time you use voice input, AppBlips asks to download a speech model (about 76 MB) from Hugging Face. It's saved on your device afterwards. Check your internet connection and try again. Once the model is saved, your recordings stay on your device.
  </Accordion>

  <Accordion title="&quot;Microphone access is blocked&quot;">
    AppBlips needs permission to use the microphone.

    - **Windows:** open **Start → Settings → Privacy & security → Microphone**. Turn on **Microphone access**, **Let apps access your microphone** and the switch next to **AppBlips**. Then close and reopen AppBlips.
    - **Browser version:** click the icon to the left of the address bar, set **Microphone** to **Allow** and reload the page.
  </Accordion>

  <Accordion title="&quot;No microphone was found.&quot;">
    Plug in a microphone and set it as the default input in your system's sound settings.
  </Accordion>

  <Accordion title="&quot;The microphone is in use by another app.&quot;">
    Close the other app that's recording, such as a video call, and try again.
  </Accordion>

  <Accordion title="&quot;Voice input could not understand that recording. Try again.&quot;">
    1. Check that the right microphone is the default input in your system's sound settings.
    2. Speak closer to the microphone, for at least a second or two.
    3. Click the microphone button and try again.

    Still failing? Close and reopen AppBlips, then [find the error details](#find-the-error-details).
  </Accordion>
</AccordionGroup>

## AI and build errors

<AccordionGroup>
  <Accordion title="&quot;rejected the API key in Settings → AI&quot;">
    Your AI provider didn't accept your key. The message starts with the provider's name, such as `Anthropic rejected the API key in Settings → AI.`

    1. Open **Settings → AI**.
    2. Check that the key is for the provider you chose and is still active in the provider's dashboard.
    3. Check that your key can use the model you picked, and that your account has credit.
    4. Click **Test connection**.
  </Accordion>

  <Accordion title="&quot;Failed to reach LLM endpoint&quot;">
    AppBlips couldn't connect to your AI provider. Check that your computer is online, that no firewall, VPN or proxy blocks the provider, and that the provider isn't having an outage.
  </Accordion>

  <Accordion title="The build hangs, or &quot;Stream stalled: no data received for 180s&quot;">
    The provider stopped sending data for 3 minutes.

    1. Click **Cancel** next to the prompt box and send the prompt again.
    2. Check your provider's status page.
    3. Choose a lower **Reasoning** level in **Settings → AI**. Higher levels take longer.
  </Accordion>

  <Accordion title="The app was cut off or is incomplete">
    Every AI reply has a length limit, and the reply hit it.

    1. Open **Settings → AI**. If **Output tokens: building** has a number in it, click **Use default** to go back to 64,000. If you don't see the field, the server sets the limit and you can't change it.
    2. Ask for the rest, for example `Finish the parts that are missing`.
    3. For a very large app, build in steps: the main screen first, then one feature per prompt.
    4. Some models have a low limit of their own. Try another model.
  </Accordion>

  <Accordion title="&quot;turned the request down&quot; or a rate limit error">
    A message such as `OpenRouter turned the request down: …` comes from your AI provider, and the text after the colon is its reason. Common causes:

    - **No credit left** on your provider account. Many providers report this as a rate limit.
    - **Too many requests** for your provider's limits. Wait a minute and try again.
  </Accordion>

  <Accordion title="&quot;Sign in with Google or GitHub to use Free AI&quot;, or &quot;The Free AI sign-in couldn't load&quot;">
    Some copies of AppBlips, such as [web.appblips.com](/quickstart-browser), ask you to sign in before you use **Free (no key needed)**.

    - **To sign in:** open **Settings → AI**, choose **Free (no key needed)** and click **Sign in**. If nothing appears, allow pop-ups for the site.
    - **If the sign-in won't load:** check your connection and any extension that blocks sign-in pages, then reload the page.
    - **To skip signing in:** use your own API key in **Settings → AI**.
  </Accordion>

  <Accordion title="&quot;You've used today's Free AI allowance&quot; or another Free AI limit">
    **Free (no key needed)** has limits so it stays available for everyone. The message tells you what to do:

    - `You've reached the Free AI limit …`: wait the number of minutes it shows.
    - `You've used today's Free AI allowance.` or `Free AI has used up today's allowance for everyone.`: it resets at midnight UTC.
    - `Free AI is still answering your other requests.`: wait for your other builds to finish.

    To keep building now, add your own API key in **Settings → AI**. See [Choose an AI provider](/ai-providers).
  </Accordion>

  <Accordion title="&quot;Claude declined this request&quot;">
    Claude's safety checks turned the request down, sometimes by mistake. Reword your prompt, or choose another model in **Settings → AI**.
  </Accordion>
</AccordionGroup>

## Find the error details

When something fails without a clear message, AppBlips writes details to its log. Include them when you report a problem.

<AccordionGroup>
  <Accordion title="Desktop app">
    1. Press `Ctrl+Alt+Shift+I` to open the developer tools.
    2. Click the **Console** tab.
    3. Repeat the action that failed.
    4. Copy the yellow and red lines that start with `[AppBlips]`.
  </Accordion>

  <Accordion title="Browser version">
    1. Press `F12` (on a Mac, `Cmd+Option+J`).
    2. Click the **Console** tab.
    3. Repeat the action that failed.
    4. Copy the yellow and red lines that start with `[AppBlips]`.

    If you run AppBlips yourself, AI connection messages also appear where it runs: the terminal for `npm start`, or `docker compose logs -f` for Docker. Lines starting with `[anthropic]` show each Claude request. In `[anthropic] done:` lines, `cache_read` is how many tokens came from Anthropic's prompt cache at a lower price, and `cache_write` is how many were stored for the next step.
  </Accordion>
</AccordionGroup>

The logs never contain your API key. They can include the start of an AI reply, so check what you copy before sharing it publicly.
