Already have a website, perhaps one a designer made? **Import a site** opens it in AppBlips so you can keep changing it by describing what you want.

You can import:

- **A single `.html` file:** opens as a one-page site in the Website studio.
- **A `.zip` of a plain website** (HTML, CSS, JavaScript, images): opens in the Website studio with all its pages.
- **A `.zip` of a React + Vite project:** opens as an imported site that keeps all its files. See [React projects](#react-projects).

## Import a page or plain website

<Steps>
  <Step title="Click Import a site">
    It's in the side panel. In a narrow window, open the menu (☰) to find it.
  </Step>
  <Step title="Choose your file">
    Click **Click to choose a .html or .zip file, or drop it here**, or drag the file onto it.
  </Step>
  <Step title="Check the name">
    AppBlips shows what it found, such as **Found a website with 4 pages**, and suggests a **Site name**. Change it if you like.
  </Step>
  <Step title="Open the site">
    Click **Open site**, then describe a change in the chat, such as "Change the headline on the home page to Fresh bread daily".
  </Step>
</Steps>

The site is now an ordinary Website studio project, so [export](/features/exporting) and [publish](/features/publishing) work as usual.

<Tip>
  If your page uses its own stylesheet, scripts or pictures, import a `.zip` of the whole folder. A single `.html` file can't bring the others with it.
</Tip>

### What AppBlips changes on the way in

In the Website studio, each page is a self-contained file, so AppBlips adjusts the site as it imports it. Before you open the site, it lists anything it left out or changed.

- **Home page:** the `index.html` in the top folder. A zip with several pages but no `index.html` is refused, so name your home page `index.html`.
- **Other pages:** pages the home page links to, plus other pages in the top folder. Pages in sub-folders get flat names (`blog/post.html` becomes `blog-post.html`) and links are updated. Pages nothing links to are left out.
- **Stylesheets and scripts** are built into each page that uses them.
- **Pictures** (JPEG, PNG, WebP, GIF, SVG) go into [My images](/features/tools#my-images-beta).
- **Fonts and icons** up to 60 KB each are built in. Larger files and other types, such as PDFs, are left out.
- **Common libraries** (jQuery, Bootstrap, Font Awesome, Swiper, Animate.css) load from a CDN, a free public server for code.

### Limits

- Up to **12 pages**, and **400 KB** for all pages together, including built-in CSS and JavaScript.
- Up to **25 pictures**. Extra ones show as broken images.
- A `.zip` can hold up to 1,000 files and unpack to 80 MB. A single `.html` file can be up to 20 MB.

## React projects

AppBlips can open a real React + Vite project and let you keep editing it with AI. It keeps the project's own files and folders, and exporting gives you the same project back.

### What can be imported

- React with Vite, in TypeScript or JavaScript
- Tailwind CSS v3 or v4, plain CSS or CSS modules
- React Router v6 or v7
- npm packages such as shadcn/ui, Radix, Framer Motion and lucide-react

The zip needs a `package.json` that lists Vite and React. Projects built with Next.js, Create React App, Remix, Gatsby, Astro, Vue, Nuxt, Svelte, Angular, Solid or Preact are refused, and so are monorepos.

Limits: 1,000 files (not counting `node_modules` and build output), 8 MB of code, and 150 MB of images, fonts and other files. Oversized files are skipped, and AppBlips lists what it skipped.

### Import and edit

<Steps>
  <Step title="Click Import a site">
    It's in the side panel. In a narrow window, open the menu (☰) to find it.
  </Step>
  <Step title="Choose the .zip">
    Pick the file or drag it onto the box. AppBlips says **Found a React + Vite project**.
  </Step>
  <Step title="Set up settings if asked">
    Some projects need settings. See [Sites that need settings](#sites-that-need-settings).
  </Step>
  <Step title="Open the site">
    Check the **Site name**, then click **Open site**.
  </Step>
  <Step title="Describe a change">
    For example, "Change the headline on the home page to Fresh bread daily". The AI edits the files and checks that the project still builds before it finishes.
  </Step>
</Steps>

To see another page, type its address in the bar above the preview, such as `appblips.local/about`. The bar shows only in the desktop-sized views.

<Accordion title="For designers: preparing the zip">
  1. Open the folder that contains `package.json`, `index.html` and `src`.
  2. Leave out `node_modules` and `dist`. AppBlips skips them anyway, but the zip is much smaller.
  3. Zip the folder: on Windows, right-click and choose **Send to → Compressed (zipped) folder**; on macOS, right-click and choose **Compress**.

  AppBlips never imports `.env` files, because they can hold secrets. List the public `VITE_` settings the site needs in `.env.example` instead, and AppBlips fills them in for your customer.
</Accordion>

### Sites that need settings

Some projects read settings, such as a service address or public key, from a `.env` file. AppBlips then says **This site needs a few settings** and offers two choices:

- **I'll fill in the .env settings:** enter the public `VITE_` values your designer gave you under **Public .env settings**, one per line, then click **Save settings**. They're included in exports and visible to anyone who visits the site, so never enter passwords or private API keys.
- **Use AI to remove the .env dependency:** the AI makes a standalone version you can preview and edit. Connected features such as sign-in or payments may show demo data instead. This uses your AI provider and can take a few minutes. Your original files stay in the version history, so you can undo it.

If a site needs settings only a server can use, it can't run in the preview, so choose the AI option.

### Browse and edit files

Click the **Files** tab in the preview toolbar.

- Type in **Search files…** to find a file by name.
- A dot marks files the AI changed last, and **Changed in the last edit** lists them.
- Images, fonts and videos show a preview. **Copy** copies a file's code.
- To edit a file yourself, click **Edit**, make your changes, then click **Save** (or press **Ctrl+S**, **⌘S** on a Mac). Each save is a version you can undo.

### Export the project

Click **Export** in the preview toolbar to download a `.zip`. Every file keeps its original path, and files the AI didn't touch are unchanged.

To build or host it, you need [Node.js](https://nodejs.org). Unzip it, open a terminal in the folder, then run `npm install` and `npm run build`.

<Note>
  If the AI added or removed an npm package, AppBlips tells you when you export. Use `npm install`, not `npm ci`, so the lockfile catches up.
</Note>

### Good to know

- Editing needs an internet connection, because the preview loads npm packages online.
- Imported sites can't be published from AppBlips. Export and host them yourself.
- They don't use SEO, My images, or extensions other than [Tavily](/features/connectors#tavily).
- **Settings → Data → Export all projects** doesn't include imported sites. Export each one as a `.zip` to back it up.
- In the desktop app, each imported site's files are also kept in a `site` folder inside its project folder. **Projects folder** under **Settings → Data** shows where.
