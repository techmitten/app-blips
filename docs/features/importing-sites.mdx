AppBlips can open a website someone already made, such as one a web designer built for you, and let you keep editing it with AI. It accepts three kinds of file:

| What you have | What AppBlips does with it |
| :--- | :--- |
| A single `.html` file | Opens it in the Website studio as a one-page site |
| A `.zip` of a plain website (HTML pages, CSS, JavaScript and images) | Opens it in the Website studio, with every page |
| A `.zip` of a React + Vite project | Opens it as an imported site that keeps all of its files (see [React projects](#react-projects)) |

## HTML pages and plain websites

### Import a page or a site

1. On the start screen, click **Import a site**.
2. Click the box and choose the `.html` or `.zip` file, or drag the file onto it.
3. Check what AppBlips found and the name it suggests (taken from the home page's title), then click **Open site**.
4. Describe a change in the chat, for example "Change the headline on the home page to Fresh bread daily".

The site opens in the Website studio like any site you built there: click-to-edit, pages, [Export](/features/exporting) and [Publish](/features/publishing) all work.

<Tip>
  If your page uses its own stylesheet, scripts or pictures, import a `.zip` of the whole site folder instead of the `.html` file alone. A single file can't bring the other files with it, and AppBlips tells you which ones are missing.
</Tip>

### How AppBlips brings the site in

A Website studio page is one self-contained file, so AppBlips adjusts the site as it imports it:

- **Home page:** the `index.html` file in the top folder. A zip with several pages but no `index.html` is refused, with the message "This zip has several .html pages but no index.html, so AppBlips can't tell which one is the home page. Name the home page index.html and try again."
- **Pages:** every page linked from the home page is imported, plus any other pages in the same top folder. Pages in sub-folders get simple names, for example `blog/post.html` becomes `blog-post.html`, and links between pages are updated to match. HTML files nothing links to, such as a theme's demo folder, are left out.
- **Stylesheets and scripts:** each page gets its own copy of the CSS and JavaScript it uses, built into the page.
- **Pictures** (JPEG, PNG, WebP, GIF and SVG) go into the project's [My images](/features/building-apps#using-your-own-images-beta). Pictures built into the page itself are moved there too.
- **Fonts and icons** up to 60 KB each are built into the page. Larger files, and other kinds of file such as PDFs, are left out.
- **Common libraries:** jQuery, Bootstrap, Font Awesome, Swiper and Animate.css load from a CDN (a free public server for code libraries, here jsDelivr), at the same version, instead of a copy in every page.

When AppBlips leaves something out or changes how something loads, it lists it before you open the site.

### Limits

A plain website must fit the Website studio's limits:

- At most **12 pages**.
- At most **400 KB** for all the pages together, counting the CSS and JavaScript built into each one. A large site with big stylesheets on every page may not fit.
- At most **25 pictures** in My images. Pictures beyond that are left out and show as broken images.
- A zip can hold at most 1,000 files and unpack to at most 80 MB. A single `.html` file can be at most 20 MB.

<Note>
  The AI only knows about the imported pictures while the **My images** tool is on (**Settings → Tools**). The pictures show on your pages either way.
</Note>

## React projects

AppBlips can open a real React + Vite website project and let you keep editing it with AI. The project keeps its own files and folders: when you export it, you get the same project back, ready for `npm install` and `npm run build`.

### What can be imported

AppBlips imports projects that use:

- **React** with **Vite** (TypeScript or JavaScript)
- **Tailwind CSS** v3 or v4 (including v4 setups with `@config` and `@plugin`), or plain CSS and CSS modules
- **React Router** (v6 or v7), including `createBrowserRouter`
- npm packages such as shadcn/ui, Radix, Framer Motion and lucide-react, plus packages that only add styles (such as Fontsource fonts or `swiper/css`)
- Images and fonts in `src/assets` or `public/`

A zip counts as a React + Vite project when its `package.json` lists Vite or React. Projects built with Next.js, Create React App, Remix, Gatsby, Astro, Vue, Nuxt, Svelte, Angular, Solid or Preact are refused, and so are monorepos with several packages.

A project can be at most:

- **1,000 files**, not counting `node_modules` and build output
- **8 MB of code** in total
- **150 MB of images, fonts and other files** in total

Single code files over 1 MB (5 MB for lockfiles such as `package-lock.json`) and single images or other files over 50 MB are skipped, and AppBlips lists what it skipped.

### For designers: prepare the zip

1. Open the project folder on your computer (the folder that contains `package.json`, `index.html` and `src`).
2. Delete or leave out the `node_modules` and `dist` folders. AppBlips skips them anyway, but the zip is much smaller without them.
3. Zip the folder: right-click it and choose **Compress** (macOS) or **Send to → Compressed (zipped) folder** (Windows).
4. Send the `.zip` file to your customer.

<Note>
  AppBlips never imports `.env` files, because they can contain secrets. It does read `.env.example`, so put the `VITE_*` values the site needs to display there.
</Note>

### For site owners: import and edit

1. On the start screen, click **Import a site**.
2. Click the box and choose the `.zip` file, or drag the file onto it. AppBlips recognises a React + Vite project by its `package.json`.
3. Check the name AppBlips suggests, then click **Open site**.
4. Describe a change in the chat, for example "Change the headline on the home page to Fresh bread daily", and click **Update Site**.

The AI finds the right files, edits them, and checks that the project still builds before it finishes. The preview updates when it's done. In the **Desktop** and **Full size** views, use the address bar above the preview to open another page, for example `appblips.local/about`.

### Browse the project's files

Click the **Files** tab in the preview toolbar to look through the project:

- The file list on the left shows every folder and file. Type in **Search files…** to find one by name.
- Common files and folders have a short plain-English description of what they're for, shown above the code.
- Files changed by the AI's last edit have a small dot, and **Changed in the last edit** lists them.
- Code files are colour-highlighted. Images, fonts and videos show a preview instead.
- Click **Copy** to copy a file's code. Drag the edge of the file list to resize it, or double-click the edge to reset it.

To change a file yourself, click **Edit**, type your changes, then click **Save** (or press Ctrl+S, ⌘S on Mac). Each save becomes a new version you can undo. Word suggestions appear as you type ([autocomplete](/features/live-preview#autocomplete); turn it off in **Settings → Workspace**). Images, fonts and other non-code files can't be edited here.

### Export the project

Click **Export** in the toolbar to download the project as a `.zip`. Every file is at its original path, and files the AI didn't change are exactly as they were imported.

To build or host it:

1. Unzip the file.
2. In a terminal, open the unzipped folder.
3. Run `npm install`.
4. Run `npm run build`.

<Warning>
  If the AI added or removed an npm package, AppBlips tells you when you export. Use `npm install`, not `npm ci`, so the lockfile catches up with `package.json`.
</Warning>

### Good to know

- The preview loads npm packages from the internet, so editing an imported site needs a connection.
- The preview runs Tailwind in the browser. It looks very close to the real build, and the export always keeps your real Tailwind setup.
- In the desktop app, each imported site is also saved as a normal project folder: open **Settings → Data** to find your projects folder, then look in `<site name>/site`.
- Imported sites aren't included in **Export all apps** backups. Export each one as a `.zip` instead.
- The review offer after a build isn't available for imported sites yet. The AI still checks that the project builds after every change.
